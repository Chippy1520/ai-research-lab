## What this means for Chathuka

The strongest entry path is not “train a policy” in isolation. It is to show that a learned or model-based robot capability survives timing limits, sensor noise, hardware interfaces, and repeatable validation. The daily evidence spans Figure firmware/test/power, Apptronik real-time controls and simulation, 1X manufacturing, Foundation custom electronics, and Physical Intelligence research.

### One evidence-linked portfolio/study action

Extend the existing **real-time robot-control and learning stack** with a small production-quality validation layer—do not start a disconnected project:

1. run the same controller/policy under deterministic seeds with injected sensor noise, delay, saturation, and model mismatch;
2. publish timing traces, deadline misses, watchdog/fault behavior, and task success with confidence intervals;
3. add one hardware-facing artifact: either a CAN/serial mock interface with fault injection or a documented PCB/actuator test fixture;
4. report repeatability, throughput, failure taxonomy, and recovery behavior.

This action is supported persistently across four tracked companies (controls 81 roles, embedded/real-time 72, simulation 56, C++ 47) and is reinforced by today’s 1X manufacturing and Foundation electronics internships—not by a single posting.
